# 自动内存诊断

正常应用初始化成功后，每 15 秒采集一次数字指标，并独立写入私有
`noBackupFilesDir/memory-diagnostics`。不使用请求日志的写入队列，不强制 GC，
不自动抓堆快照，不采集聊天正文、账号或凭据。采样不申请唤醒锁，设备休眠时不保证间隔。

- Java 堆占用达到上限的 80%，连续 3 次采样：记录持续高占用事件。
- 最近 30～60 秒增长至少 `max(32 MiB, 堆上限的 15%)`，且当前至少使用 65%：
  记录快速增长事件。
- 使用达到 92%：记录紧急事件，可越过普通事件冷却。
- 普通事件冷却 5 分钟，紧急事件冷却 1 分钟。阈值是取证启发式，不是 OOM 预测保证。

每次事件附带最多 20 次最近采样。采样和事件各保存当前文件及一个轮换文件，
分别在 128 KiB、64 KiB 时轮换（可超出一个记录块）。进程重启不清空文件。
用户原有“导出日志”ZIP 自动包含 `memory-diagnostics/`，普通日志为空时也可单独导出这些记录。

指标包含 Java 堆占用/上限、native allocator 已分配字节、最近一次系统 trim level、
流的缓存事件数/最大未消费事件数/订阅者数、展示缓冲字符数。流和展示缓冲采用弱引用注册，
最多追踪最近 512 个来源；这些计数不是全进程对象清单，不能相加当作堆字节数。
独立写盘失败时采样线程继续尝试；采样自身遇到 OOM 则停止，不在崩溃路径分配诊断报告。
