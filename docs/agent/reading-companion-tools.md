# 阅读伴侣工具接口

普通对话先发现工具包简介，再通过 `use_package` 加载接口及使用说明。CLI 模型通过
`search` 发现接口时同时获得该包的使用说明。

## 工具分组

- `reading_companion`：选书、当前上下文、人物和章节回顾、读者记忆。
- `reading_companion_tasks`：`start_task`、`get_task`、`list_tasks`、`cancel_task`。
- `reading_companion_manage`：文件浏览、摘要范围设置、段评和审计记录。
- `reading_companion_auto_commentary`：既有后台自动段评的状态和配置。启用手动生成任务不要求启用后台自动段评。

新对话接口使用从 1 开始的章节号；Kotlin 内部仍使用零基索引。现有管理界面的
`summary_batch_prefs` 保留一基章号，并支持 `book_id`，读写设置时可与生成任务绑定同一本书。

## 生成任务

`start_task` 接收 `kind=summary|commentary`、`count`，可传 `book_id`、
`start_chapter`、`end_chapter` 和 `request_id`。省略书籍时在启动时固定当前选书。
`mode=fill_missing` 补缺；段评还支持 `mode=regenerate` 重生成明确的起止范围。
补缺模式的 `count` 为处理预算；段评重生成使用明确起止范围（最多 10 章）。
同一次请求发生传输重试时复用 `request_id`，不要另发一个新的生成请求。
要再次生成时使用新的 `request_id`；旧标识会返回原任务，包括原任务已结束的情况。

启动立即返回 `task_id`。用该 ID 查询状态或取消；`list_tasks` 可找回近期任务。
任务继续使用现有逐章子代理及审计记录，取消不会删除已完成章节。
任务记录保存在 `reading.db`，原 JSON 任务文件只导入一次且保留原件。任务关联逐章尝试与 subagent run；详细审计过保留期后仍保留章节结果。进程重启后未完成任务标记为 `interrupted`，
不会自动重放或自动产生新模型费用。它不承诺进程退出后仍继续生成。

内部提交工具成功返回 `interruptTurn=true` 时正常结束本轮；`submit_comments` 和摘要专用任务的 `submit_summary`
校验失败时允许模型修正后重试，失败结果要求中断时仍按错误处理。段评正文完整保存，不按 80 字静默截尾。
此前已被截断保存的正文无法自动还原，需要对相应章节重新生成段评。

## 文件与人物

人物查询基于 `characters.md` 和有效章节文件，不再依赖缺少生产路径的人物 FTS 索引。
这些文档中的人物看法和读者记忆仍需与小说原文证据区分。

`read_persisted_file` 接收 `offset` 和 `max_characters`，使用结果中的 `nextOffset`
继续读取。默认每次读取 16000 字符。路径仍需属于当前书籍的有效文件目录；
文件查看页以分段方式加载。

书籍文件按应用包名隔离，位于 Operit 外部存储根目录下的
`reading_companion/installations/<packageName>/books`。首次访问时将旧
`reading_companion/books` 完整复制到当前安装的目录，完成后启用；保留旧目录，后续不重复覆盖。
稳定版和 Dev 各自复制一次，此后的摘要、角色段评和读者记忆互不覆盖。reading 数据库不迁移。
摘要与元数据通过待完成记录共同发布，进程中断后由下一次章节访问完成恢复。保存方法返回实际保留的文本，索引与响应使用该文本，人工修改优先于新模型候选。

新段评先写入章节 `revisions/<revision>`，再在 reading.db 的发布事务中切换当前 revision。注解和文件浏览只读取已提交版本；主聊天的检索路径也返回有效文件而非可递归扫到历史版本的目录；旧目录在没有发布指针时继续作为读取来源。

生成任务的搜索始终绑定任务书籍；摘要提交失败可修正，重复调用且没有新证据时结束任务并记录原因。
取消和选书变更导致的 `superseded` 分别显示实际停止状态，已完成文件保留。
后台模型预览使用全局 CHAT 映射；对话内生成沿用调用方模型。每章以多轮子代理处理，默认带入前 4 章上下文。
旧原生批次动作保留给既有调用方，新的工具目录和侧栏生成入口使用任务接口。


### 生成任务与聊天检索分离

生成任务的初始输入由程序构造，包含固定任务说明、带段落锚点的目标章、近期前文以及角色信息。生成 subagent 无须主聊天先搜索。补查旧剧情只使用 `reading_commentary_grep` 定位当前任务书籍目录中的有效文件，再用 `reading_commentary_read_file` 按字符偏移分页读取原文。grep 返回路径、行号、字符偏移和下一页；不调用查询分析或重排模型。生成工具白名单不含 `task`。

主聊天通过渐进使用说明获取本书路径，自行 grep 和读取文件；复杂检索可委派 `task`，与生成任务互不依赖。生成仍使用多轮 subagent，无固定轮数上限、不回退单发；后台保持全局 CHAT 模型。


### 只缓存已下载旧章

任务支持 `kind=cache, count=1`：逐章扫描当前书籍的已读旧章，完整快照已存在则跳过，Legado 未下载的章节也跳过并继续扫描。使用独立的 `book/cachedReadableContent/query` 接口，缺少缓存返回 `cached=false`，不调用 WebBook 或模型。不支持新接口的旧 Legado 会明确失败，客户端不回退旧的联网正文接口，因此需要同时更新 Legado。

入口提供“缓存已下载旧章 / 继续缓存”，任务显示检查数量、已有缓存和未下载跳过数量；暂停保留文件，重开跳过完整快照。首次手动完成后，进入阅读伴侣或聊天获取上下文时发现阅读进度前进，会继续增量缓存。取消、失败或进程中断后不会自动重放，需手动继续；同一进度下新下载的章节可再次手动缓存。

`get_local_files.cacheCoverage` 和生成 grep 的 `coverage` 给出旧章本地快照数量及缺失数量。快照可能不完整或过期，未命中不是“书中没有”；先换短词、别名或拆词检索，仍无证据时说明局限。
