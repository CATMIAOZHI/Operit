# AI 工具权限说明

本文介绍新版 AI 工具权限机制，帮助你快速理解「全局默认 + 单工具例外」的工作方式，并给出一些推荐用法。

---

## 一、权限模型概览

设置页最上面的滑块一共五档：

- **禁止（FORBID）**：直接拒绝执行，不会调用该工具。
- **询问（ASK）**：每次调用前都弹窗询问。
- **自动审核（AUTO_REVIEW）· 严格**：可确认位于当前工作区内的操作直接放行，其余原本需要询问的操作交给独立的审核代理判断，每次调用都重新判断；审核失败、超时或无有效结果时转回由你确认。
- **自动审核（AUTO_REVIEW）· 快速**：和严格档一样，区别是最近的审核结论是低风险时，后面的调用直接复用，不再启动审核代理。
- **允许（ALLOW）**：直接执行，不再询问。

「自动审核」这档不是系统沙箱，也没有系统级兜底。

在此基础上，权限由两层共同决定：

1. **全局默认权限**：决定「所有工具的默认行为」，也就是上面那个滑块。
2. **单工具例外配置**：对某个具体工具设置特殊规则，覆盖全局默认。

最终某个工具实际采用哪种权限等级，由下述规则决定。

---

## 二、全局默认权限

「全局默认权限」是整个系统的基础策略，适用于**所有没有单独配置的工具**。设置页最上面的滑块就是这个设置，一共五档，从左到右越来越宽松：

| 档位 | 含义 |
| --- | --- |
| **禁止** | 所有工具都不会运行。 |
| **询问** | 每次调用工具前都弹窗问你。 |
| **自动审核 · 严格** | 可确认位于当前工作区内的操作直接放行；其余交给审核代理，每次调用都重新判断。最安全，也最慢。 |
| **自动审核 · 快速** | 和严格档一样，另外用一个轻量模型异步评估当前这组操作；结论是低风险时，后面的调用直接放行。 |
| **允许** | 所有工具直接运行，不再询问。 |

> 只要某个工具没有配置「单工具例外」，它就会完全按照滑块选的那一档执行。子代理协作工具是唯一的例外，见下。

全新安装（或清空应用数据）后，滑块默认停在**自动审核 · 快速**这一档，也就是上表第四档：工作区内的操作直接放行，其余交给审核代理，并且会复用最近的审核结论。已经装好、但从没改过这一档的用户，升级后同样会落到这一档；你一旦自己选过某一档，就保持你选的那一档。

「自动审核」原本是一个单独的档位开关，现在拆成滑块上相邻的两档。两档的区别只有一条：**一次审核的结论能不能被后面的调用复用**。严格档不复用，每次都重新审；快速档会复用，所以更快，也更依赖模型判断。

聊天输入框那里的「工具」菜单里也是同一个滑块，改任意一处，另一处跟着变。

### 子代理协作工具默认允许

AI 把工作交给另一个代理的那几个工具默认就是「允许」：

- `spawn_agent`、`send_message`、`followup_task`、`interrupt_agent`
- `list_agents`、`wait_agent`、`list_agent_models`
- 旧版子代理工具 `task`

原因：这些工具本身不碰你的数据，它们派出去的活会在每一个真正的工具调用上照常走审核，所以对「转交」这一步再问一次只会增加打扰。

它们会出现在「允许」分组里，但不带移除按钮，因为它们本来就没有单工具配置。你仍然可以给其中某一个设置例外：在其他分组里用 `+` 把它加进去（例如加进「禁止」），例外规则照样优先。

全局默认设为「禁止」时，这些工具也会跟着被禁止——那是一个白名单，不该被默认值悄悄打洞。这时你可以在「允许」分组里用 `+` 把它们加回来。

### 快速档在做什么

快速档参考了 OpenAI Codex 的自适应评分设计，只做三件事（计数单位不同：这里按「工具批次」计数，Codex 按单次工具调用计数，因此这里的复用窗口更宽）：

1. 按「工具批次」计数。每派发一批工具算一步，最近两步内的低风险评分都还能用，跨工具类型也照样复用。只包含「不需要审核」的工具的批次只让评分变旧，不会把它作废。
2. 评分只可能**减少**审核。判成高危、还没算完、算失败、网络离线、或者评分模型连续失败进入冷却，都照旧交给审核代理；它自己从不拒绝操作。
3. 评分和当时的授权绑定。你发了新消息、改了 AGENTS.md 或 user.md、换了工作区、改了审核策略、换了评分模型、或者刚被拒过一次，旧评分立刻作废。

快速档依赖模型判断，没有系统级沙箱；工作区放行规则和「自动审核」的其他部分不受档位影响。

## 三、单工具例外配置

在全局默认之外，你可以对个别工具设置「例外规则」。

在设置页中，每个权限分组（允许 / 自动审核 / 询问 / 禁止）下，都可以手动添加工具：

- 把工具放进 **允许** 分组：代表「不管全局怎么设置，这个工具都允许自动执行」。
- 把工具放进 **自动审核** 分组：代表「这个工具按自动审核规则执行」，用的是滑块上当前选的严格或快速档。
- 把工具放进 **询问** 分组：代表「这个工具每次调用前都要你确认」。
- 把工具放进 **禁止** 分组：代表「这个工具始终禁止执行」。

当某个工具存在例外配置时：

> **实际权限 = 单工具例外等级**，而不是全局默认。

如果你想让某个工具**重新回到跟随全局默认**的状态，可以：

- 在分组中再次点击该工具，或
- 在工具选择对话框中取消勾选该工具。

此时，该工具的例外配置会被清除，重新根据全局默认执行。

## 四、推荐使用场景

下面是几个常见、易理解的权限组合示例：

### 场景 1：整体偏保守，只信任少数工具

- 全局默认：**每次询问（ASK）**
- 把你完全信任的只读/无副作用工具（如代码搜索、计算器等）加入 **允许（ALLOW）** 分组。

效果：

- 绝大多数工具在使用前都会弹窗确认；
- 只有你明确加入「允许」分组的工具会静默执行。

### 场景 2：极端安全模式，只允许少数白名单工具

- 全局默认：**禁止（FORBID）**
- 把你信任的工具按需要加入 **允许 / 每次询问** 分组。

效果：

- 默认所有工具都被关掉；
- 只有你点名加入分组的工具才有机会被调用，且以你选择的权限级别执行。

## 五、小结

- 全局默认 = 底线策略，决定「没有例外时」所有工具的行为。
- 单工具例外 = 覆盖策略，让你可以对少数工具做更细粒度的控制。
- 没有出现在任何分组中的工具，一律视为「没有例外配置」，完全跟随全局默认；唯一的例外是子代理协作工具，它们默认「允许」。

如果你在配置过程中遇到不符合预期的行为，可以优先检查：

1. 全局默认当前设置为什么？
2. 该工具是否出现在某个分组中，被设置了例外规则？

根据这两个信息，基本可以判断出当前行为的原因。
