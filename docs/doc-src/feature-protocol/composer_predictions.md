# 智能输入预测（Composer Predictions）

“智能输入预测”默认开启，可在全局显示设置中关闭。已保存的关闭选择会保留；重置显示设置后恢复开启。
开启后，普通聊天成功完成一轮回复时，可额外调用当前聊天模型，预测用户下一条消息；
这可能产生额外 API 费用。

## 输入交互

- 预测仅在真实草稿为空且没有输入法 composing 区间时，以灰色文字显示。
- 有灰色预测时，双击输入框的编辑区（包括空白处）可将其写入真实草稿，并把光标移到末尾；不会自动发送。
- 两次点击间距使用 Android 的双击容差；拖动仍按触摸移动阈值判断，旁边的功能按钮不触发采纳。
- 手动输入、粘贴、语音输入或添加附件隐藏预测；清空草稿且移除附件后恢复同一轮缓存，不重新请求模型。附件存在时也不能通过无障碍操作采纳旧预测。
- 采纳后再清空也可以恢复。预测不计入真实输入字数，不启用发送按钮。
- 无障碍用户可以使用“采纳预测消息”操作。

主聊天界面的 Agent、Classic 与全屏输入共用预测状态。独立悬浮窗具有另一套会话和
草稿生命周期，本版不为它发起预测。群聊编排、内部消息和子代理自己的回复也不触发预测。

## 完成边界与结果身份

`EnhancedAIService` 在当前执行结束前复制已经准备好的有效历史和模型配置，避免重新执行
历史准备、提示词 hook 或记忆写入。`MessageProcessingDelegate` 只在成功保存最终回复后发布快照。
协作任务、待投递消息或任务预留尚未结束时，先保留快照，待协作状态变化后重新判断资格。

预测由独立 coordinator 管理，区分运行中、成功有文本、成功无文本和失败。
结果绑定会话、来源回复轮次和独立请求身份；再结合当前历史、模型配置与执行状态验证。
新消息、新轮次、切换/删除会话、撤回/编辑/重新生成来源回复、关闭功能等操作使旧结果失效。
即使取消后的请求迟到返回，也不能覆盖新的预测。草稿编辑不属于预测失效条件。
调整思考开关或强度时，已生成的预测保留并可继续采纳，不重新请求；尚未完成的预测取消。

## 请求隔离、缓存与费用

预测使用不可变快照和全新的模型 provider，不进入普通聊天的 provider 实例缓存，
取消或释放预测不会关闭主请求。API key 池轮换只在请求内部进行，
不更新原模型配置的轮换索引。

预测在已有历史末尾追加预测指令，不把指令或结果保存为聊天消息，不执行 Agent 循环或
工具调度。请求会原样复刻已完成那一轮的线上形状：同一份工具定义、同一个 provider 会话标识、
同一份搜索接地设置，以及同一份会话级请求头（每请求的身份头如 `x-grok-req-id`、Antigravity
的 `requestId` 按请求各自生成，天然不同），只在最后追加预测指令。provider 只在工具、历史序列化方式和会话
标识都不变时才复用已预热的提示词前缀，因此复刻形状是命中缓存的前提；工具不能被调用另有
两道保证：预测指令明确禁止调用工具，任何回传的工具标记都会被判定为无效预测而不是显示出来。
预测同样跟随已完成那一轮的思考开关与思考参数，而不是自己关掉思考：关闭思考既会明显降低
质量，也会让部分适配器改写消息历史、改变已被缓存的公共前缀；供应商按思考强度匹配缓存时，
强度也必须一致。预测保留调用方实际发送的标量思考参数（如 `reasoning_effort`、
`thinking_level`、`enable_thinking`）及其 token 预算（`thinking_budget`、`thinkingBudget`、
`budget_tokens`）：provider 要求预算落在请求的输出上限之下，而预测沿用的正是完成那一轮的
上限，所以调用方当时发过的预算按构造就是合法的，照搬即可保持强度一致。对象形式的
`reasoning`、`thinking`、`output_config` 和 `thinkingConfig` 会校验已知思考字段和类型，
再原样保留参数、类别和顺序；遇到未知字段或无法解析的配置，本次预测不发起请求，
不会静默改用默认思考强度。
仍会过滤可能覆盖消息、工具或远程会话的任意自定义参数（`customParameters` 会被清空）。
思考内容与正文共用同一个流，
展示前会按现有规则剥离思考块，未闭合的思考块按无效预测处理，因此思考不会被当成用户下一条消息。
Codex 登录（OPENAI_CODEX）和 Zen Free 已开放：预测复用各自适配器，Codex 继续使用应用内
OAuth 登录、同一个会话标识和系统指令转换；Zen Free 继续使用可选 API Key，并按模型选择
Chat Completions 或 Responses。Zen 的保留工具定义由本地适配器补充，主聊天和预测使用相同
规则，预测路径不接工具执行器。预测也会消耗对应账户额度。
插件 provider 与非文本模式目前不运行预测。插件虽有实例级取消 ID，但共享 JavaScript
运行环境且可直接调用应用工具，尚不具备预测需要的隔离和不执行工具契约。

输出上限同样沿用完成那一轮自己的值，预测不再自设一个更小的上限：自设上限会截断思考块，
也会改变 provider 的计费口径。完成那一轮带了 `max_tokens`/`max_completion_tokens`/
`max_output_tokens` 就按原字段原名带过去，没带就同样不带，由服务端默认值决定。

已知限制：推理档位越高，思考块越长，而思考与正文在多数适配器里共用同一个输出上限，所以
一次高推理强度的预测可能要花上一两分钟才出现。请求仍保留一个 5 分钟的兜底超时——在用户
还会去采纳建议的时间尺度上等于不设超时，但请求不会永远挂着；主要的停止方式仍是取消：
新一轮对话会取消上一次预测，OpenAI 系适配器另有停滞看门狗会丢弃长时间收不到数据的流
（Claude、Gemini 适配器没有该看门狗，只靠 5 分钟兜底），读流阶段还有一个约 256 KB 的缓冲上限。
自身超时记为失败并释放请求；切换会话等外部取消仍按取消处理。

已知限制：工具选择模式仍是 provider 默认的 `auto`，模型偶尔会真的选择调用工具。要改成禁止调用
需要按 provider 分别处理，而现状是三种不同形状：OpenAI 系适配器会无条件写入自己的
`tool_choice: "auto"`，覆盖任何从参数注入的值；Anthropic 适配器完全不写 `tool_choice`，
注入对象形式的 `{"type":"none"}` 可以生效；Gemini 既不写也不覆盖 —— 它用
`toolConfig.functionCallingConfig`，往请求体塞一个未知顶层字段反而可能被拒。
因此本版不覆盖，而是让被拒的工具调用落回"无效预测"。这只影响命中率，不影响安全性。

请求保留允许的采样参数，沿用完成那一轮的输出上限，另有超时及输出格式检查；失败或无合适文本
不会影响主聊天。用量经过现有 token 统计包装器，归入单独的“智能输入预测”类别。
实际用量和费用的精度仍取决于供应商返回数据及现有统计能力。

复刻已完成请求的形状是为了让公共前缀一致，但缓存是否命中仍取决于供应商：按前缀精确匹配的
供应商会命中到指令之前的部分，只按整份请求体做哈希的中转网关不会命中。推理参数和输出上限
通常不参与前缀，但部分供应商按思考强度匹配缓存，所以预测仍跟随完成的思考设置；即便如此
也不保证任何供应商都命中，且不把复用本地对象等同于缓存命中。

## Codex 设计参考

参考 OpenAI Codex 提交
[`c3d3b142d10f4316b46e35aad7e5317e7e506cb7`](https://github.com/openai/codex/tree/c3d3b142d10f4316b46e35aad7e5317e7e506cb7)：

- `codex-rs/app-server-protocol/src/protocol/v2/thread_prediction.rs`：会话/来源轮次身份，以及
  completed（文本可空）与 failed 的区分。
- `codex-rs/app-server/src/request_processors/thread_processor.rs` 与
  `codex-rs/core/thread_manager.rs`：从已加载父上下文创建临时预测 fork、继承有效配置和历史。
- `codex-rs/app-server/tests/suite/v2/thread_fork.rs`：比较父子请求上下文，不能由此推断实际缓存命中。

上述版本的 `thread/prediction/request` 仍返回未实现；公开代码没有完整的预测生成器或
桌面输入框交互。本实现自行设计 Android UI、预测提示词、生命周期和隔离请求。
Codex 的临时 fork 本身不等于禁止工具。Operit 这里声明了与已完成请求相同的工具定义，因此
“不执行工具”不再来自空工具列表，而是来自三件事：预测指令明确禁止调用工具、任何工具标记都
会被判定为无效预测，以及预测请求这条路径完全不接工具执行。
