# 工具调用问题记录

入口：工具箱 → 日志查看器 → 工具调用问题。

记录 AI 对话和子代理中的两类问题：

- 工具最终返回失败，包括参数校验失败、工具不存在和执行异常。
- 工具调用传入了接口未声明的参数，即使最终返回成功。例如 `read_file` 的
  `startline`、`endline` 会被记录；`read_file_part` 的 `start_line`、`end_line` 不会。

参数检查复用系统工具和实际执行器的声明。工具包使用本次执行器持有的有效工具定义，
包括动态安装、更新、状态工具；MCP 使用本次调用取得的 `inputSchema`，不额外请求网络。
工具包/MCP 参数表不做启动缓存，也不按同名包猜测归属。代理调用同时检查代理外层和
目标工具的参数，但日志保留原始代理参数，目标问题以 `params.` 标明位置。
没有可用参数声明的工具只记录执行失败，不推测参数是否合法。
MCP 显式允许动态属性或使用组合模式时，不猜测未列出的参数是否有效。
未声明不一定代表执行器没有读取该参数，记录用于排查接口与实际调用的差异，不拦截调用。
取消和拒绝授权不计入。流式中间结果和异常回调不单独计数，同一次调用可以同时有两类问题。

记录仅包含内部去重标识、时间、工具名、原始参数、错误说明和问题分类；不保存对话、模型、工作区等上下文，
也不保存成功的工具输出。参数值和工具返回的错误信息保留原样，不套用聊天显示的截断限制。
仅记录安装此版本之后的新调用，不反查历史。

页面按工具汇总，支持全部时间、近 24 小时、近 7 天筛选与分页查看。
一键导出当前筛选的**全部记录**到 `Download/operit/operit_tool_errors_时间.zip`，
包含 `summary.json`（各工具的记录数、执行失败数、参数问题数）
和 `errors.jsonl`（每行一个完整记录，参数为有序数组，保留重复参数名）。
两类计数可能重叠；总记录数代表有问题的调用次数，而非失败率。

数据保存在应用私有的 `tool_errors.db`，独立于聊天数据库。
查询、写入和 ZIP 导出均在 IO 线程执行；统计页面不订阅普通聊天 token 流。
清除应用日志不删除这些独立记录。
