# 每个模型的协议处理

在模型配置的 API 设置中，使用多模态区域的模型选择器选中模型，然后设置「协议处理」。
配置按模型名保存，调整模型顺序不会互换设置；新模型默认继承提供商。

保存模型设置时，会读取本地模型目录自动适配，不主动联网；添加模型后马上离开页面也会适配。
协议按账户端点匹配提供商，再匹配其下的模型 SDK 与 `interleaved.field`；OpenAI、xAI
官方地址和 OpenRouter 等保持提供商原有协议的条目只补思考档位，且只在请求会发送这些档位的
提供商类型（OpenAI 兼容、Responses、OpenCode）上写入，Anthropic、Gemini、OpenRouter
提供商类型不写。图片、音频、视频能力和上下文、输出上限按模型名匹配能力目录。

自动适配只补空缺，三类各自判断：没有协议的模型补协议，没有上限的模型补上限（目录没有上限就
不写），能力只补给还没定下来的模型。手动改过能力、或按目录设过能力的模型记为已定，之后不再
自动改；旧版本保存的配置，已有单独能力的模型都视为已定。设置页只写入自己改动的字段，
后台或 AI 同时补上的内容不会被覆盖。Orbit 新建或切换模型、AI 修改模型配置时也走同一套规则。

两个目录各自记录更新时间：每周从 models.dev 更新一次，失败一天后重试；应用启动时和后台
每天检查一次。目录内容或应用版本变化后，会给所有配置补齐一次，没补完下次继续。
「重新适配」会先保存当前设置、联网更新目录，再按目录重设全部模型。模型单独填写的端点
一定保留；目录条目是继承提供商时，原来的协议也保留，否则用目录的协议。更新期间被手动改过的
模型保留改动。目录更新失败时用本地目录，结果以提示显示。恢复备份后也会按本地目录补齐。
Go 使用独立的 `opencode-go` 条目，不使用模型原厂或 Zen 的协议配置。
Go 部分 Qwen 模型的 SDK 记录与官方端点表不同，对已核对的模型以官方 Messages 端点为准。

每个模型的「上下文和输出上限」来自能力目录，可手动修改，留空沿用聊天设置。聊天的上下文窗口
取用户设置和模型上限中较小的一个，开启最大上下文时也不超过模型上限；启用最大输出时，
请求的 `max_tokens` 同样不超过模型的最长输出，自定义参数里的回复长度参数也一样。目录里找不到的模型会在设置页提示手动设置。

- **继承提供商**：沿用原有处理方式，已有配置升级后保持原样。
- **Chat Completions（标准）**：使用 OpenAI 兼容格式。
- **Chat Completions（回传 reasoning_content）**：将历史思考内容放入 `reasoning_content`，不自动添加 Kimi 的 `thinking` 参数。
- **OpenAI Responses**：使用 Responses 格式及现有加密思考上下文处理。
- **Anthropic Messages / Gemini 原生**：使用对应的现有协议实现。
- **DeepSeek / Kimi / MiMo**：使用现有专用处理，包括该实现的思考参数与上下文回传。

同一账户仍共享 API Key、自定义请求头和限流设置。模型级协议设置只决定请求协议与端点；
它不会自动检测服务端支持哪些协议，也不会补全服务端未返回的思考数据。
本地 MNN、llama.cpp 和插件自定义提供商继续使用各自的执行方式。

模型端点留空时继承账户地址，并将标准的 `/chat/completions`、`/responses`、
`/messages` 后缀转换为所选协议对应的路径。基础地址由对应协议继续补全。
非标准路径可为模型单独填写端点；末尾 `#` 延续现有的禁用自动补全语义。

例如 Go 账户地址使用 `https://opencode.ai/zen/go/v1/chat/completions`，
某模型选择 Responses 后会请求同一地址下的 `/v1/responses`；
选择 Anthropic Messages 则请求 `/v1/messages`。
连接测试、聊天、子代理和功能模型均使用选中模型的协议设置。
