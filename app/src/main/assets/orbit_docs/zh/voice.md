# 语音

用户可以用语音输入文字、听你朗读，也可以请你制作可播放的语音文件。
语音输入、消息朗读和生成音频是不同功能，不要把它们说成实时语音通话。

## 语音输入

用户点聊天输入区的麦克风后，应用会录音并识别成文字，填入可编辑的输入框。
用户可以检查、修改后再发送；不要把开始录音说成消息已经发送。
录音需要麦克风权限，识别效果和可用性取决于当前语音识别服务及其配置。
需要授权时可用 `orbit_permission_card permission=microphone` 放权限卡。

微信频道也支持用户发语音，但微信服务器会先把语音转成文字再交给你。
转写失败时，你只会收到一条说明，不能假装听到了原始录音。
连接方式和频道限制见 [weixin.md](weixin.md)。

## 朗读与语音设置

聊天提供消息朗读和自动朗读选项，实际使用应用当前配置的语音服务。
语音配置分两类：朗读（tts）和语音输入（stt），每类可以有多个配置，各用一个。
先用 `orbit_voice action=profiles` 看有哪些、正在用哪个（看不到密钥，只有 has_key）。
换用、新建、换密钥、删除分别用 `request_switch`、`request_create`、`request_key`、`request_delete`。它们都会放一张批准卡片，要密钥时用户在卡片里填，你看不到。放卡后用一句话结束本轮，用户批准后你会收到一条隐藏消息说明结果。
语速、音调、请求头这类细项，或用户想自己调时，用 `orbit_voice action=request_settings` 放一张语音设置卡，用户点开后自己修改。

生成语音文件使用下面的手机系统 TTS 引擎，不要承诺它会沿用消息朗读所选的服务或声音。

## 制作一段语音

用户要语音消息、简报、故事或其他可以反复播放的音频时，用 `orbit_voice action=speak`。
`text` 填要读的文字；`title` 可选，作为不含扩展名的文件名。

需要指定声音时，先用 `action=voices` 查看真实可用的声音。
结果中的 `name` 是 `voice` 接受的名字，`locale` 是语言，`needs_network` 表示该声音是否需要网络。
不要编造声音名；指定不存在的名字会报错。不指定时，含汉字的内容选中文声音，否则用手机默认语言；读其他语言时，先用 `voices` 查看并明确指定。
声音来自手机的 TTS 引擎；不能保证手机有某种音色，也不能承诺声音克隆。

一个文件最多 6000 字符，多人台词按所有台词合计。
更长的内容拆成几段生成；音频过大或引擎失败时也按返回错误缩短、拆分或换声音，不把失败说成生成成功。
手机需要正常工作的系统 TTS 引擎和已安装的语音资源；缺少时请用户检查系统“文字转语音输出”等设置。

## 多人台词音频

用 `orbit_voice action=podcast` 把多个人的台词合成一个音频文件。
`script` 是 JSON 数组，例如 `[{"speaker":"A","text":"今天聊什么？"},{"speaker":"B","text":"聊聊你的计划。"}]`。
每项写 `speaker` 和非空的 `text`，同一说话人使用相同名字。

可选的 `voices` 是说话人到声音名的 JSON 对象，例如 `{"A":"从 voices 返回的名字","B":"另一个真实声音名"}`。
省略时工具会尽量给每人分配同语言的不同声音；声音不足时可能共用声音，以音调区分。
台词写成短句、自然来回，不把它描述成真人参与、实时连线或多人会议。

## 把音频交给用户

成功后工具会返回 `path`、实际使用的 `voices` 和 `markdown`。
把返回的 `markdown` 原样放进回复，用户就能在聊天里看到播放器。
文件保存为当前 Orbit 的 `files/voice/` 下的 WAV，也能在构建页的文件中找到。
需要重新发送已有音频时，用 `orbit_file action=send`。
只告诉用户设备路径不算交付；是否完成以工具实际返回为准。
