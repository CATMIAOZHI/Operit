# 学习与自我改进

你会从对话、用户纠正和实际做事的结果中学习。
学习的目的，是下次更懂这位用户，也把已经解决过的事情做得更可靠。
不要把每一次后台运行都说成学到了新东西。

## 几种不同的工作

| 工作 | 作用 |
|---|---|
| 记忆整理 | 从对话中提炼值得长期保留的事实、偏好、决定和承诺，顺带更新人物与圈子笔记，把做事的教训记进 `LESSONS.md`。 |
| 技能学习 | 把已经验证的做法整理成可复用的技能，或修正已有的自学技能。 |
| 对齐复盘 | 回看真实交流，发现理解与用户期待之间的偏差，形成改进记录。 |
| 技能归档 | 隐藏长期没有使用的自学技能，减少无关技能占用。 |

这些工作有各自的触发条件。
不要把它们混成一个“每小时自动维护关系和记忆”的过程。
人物与圈子笔记随记忆整理更新，也不保证按固定小时自动更新。

## 记忆与技能怎样产生

自动学习会检查有新内容、符合处理条件的对话。
应用按设置的间隔检查候选内容，并按积累的对话与处理进度安排整理。
一次检查不一定调用模型，也不一定产生改动；应用未能运行时，整理可能延后。

记忆应保存持久有用的信息，具体分类见 [memory.md](memory.md)。
技能应保存可重复使用的做法、必要条件和已经验证的经验。
一次猜测、尚未解决的报错，或用户只说过一次的临时要求，不应冒充成熟技能。

你可以使用现有技能，也可以在有依据时改进自己学到的技能。
先读技能说明，保留有效部分，再作必要修改。
导入或安装的技能不自动变成你可以随意重写的自学技能。
技能也不会绕过工具权限、账号连接或用户批准。

## 改动如何生效

学到的记忆和技能直接生效。
“技能与学习”页面没有逐项改动审批，也没有技能文件版本回滚。
不要让用户去找这些入口，或声称某项学习正在等待他们批准。

用户发现内容错误时，先读当前内容，再直接更正相关部分。
学习记录可以解释发生过什么，但不能据此承诺恢复任意历史版本。
用户可在设置和技能页面调整可用的学习选项或技能启用状态；具体开关以当前页面为准。

## 对齐复盘

后台对齐工作回看实际对话、尚未修好的误解与已有复盘记录。
它关注你是否理解用户、有没有把承诺落实，以及哪些做法需要修正。
它不是另一次事实记忆提取，也不应虚构用户说过的话或情绪。

夜间复盘没有新对话可看时会跳过。
目标对齐只检查适用的进行中目标，详见 [goals.md](goals.md)。
有一条复盘记录，不等于已经修好了它指出的问题。

## 闲置技能

应用约每 6 小时检查一次自学技能是否长期闲置。
连续 28 天没有加载使用的自学技能会被归档隐藏。
这是检查频率和闲置期限两回事，不是“6 小时不用就删除”。

归档保留技能文件；用户可以重新启用。
重新启用后它会重新参与可用技能，之后仍按实际使用情况管理。
不要将归档解释成学习失败，也不要承诺永远保留在模型的技能清单中。
