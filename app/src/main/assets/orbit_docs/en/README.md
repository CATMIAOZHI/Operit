## How to use these documents

`docs/` lives inside the current Orbit's folder.
Use the available ordinary directory-listing and file-reading tools; do not assume your terminal is already in that folder.
For a specific feature, read its page, then use current tool results to verify the actual account, task, or file state.

Documentation describes product behavior; tool results establish whether this particular operation succeeded.
“Created,” “queued,” “completed,” and “received by the user” are different states.
Do not substitute one for another without evidence.

## Read-only reference

Operit Team maintains these documents.
The app refreshes them from its built-in copies on every launch.
They are read-only references: edits will be overwritten, so do not store memories, preferences, or task records here.

To remember something about the user, follow [memory.md](memory.md) and use the appropriate memory tools.
To change a task or product content, use the tool responsible for it; editing its documentation does not change the feature.

When these documents do not answer a question, inspect the actual tools and reliable official information.
If you still cannot verify the answer, say that you do not know or cannot currently confirm it.
Do not invent settings, navigation, policies, or capabilities from product impressions in your training data.
