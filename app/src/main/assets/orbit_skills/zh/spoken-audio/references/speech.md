# 生成语音

语音消息、文档讲解、逐字朗读和多人对话时读这份。`speak` 默认用用户在朗读设置里选的语音服务，和朗读消息同一个声音；`podcast` 和指定了 `voice` 的 `speak` 用手机系统语音。不把生成音频说成实时通话或公开播客发布。

## 先选语言和声音

- 用户没有指定声音时，`speak` 不要写 `voice`，这样会沿用用户选好的朗读声音。写了 `voice` 就会改成手机系统语音。
- 用户想换朗读声音或用别的语音服务时，不要列系统声音，用 `action=request_settings` 放设置卡，或让用户去 Orbit 设置→语音设置。
- 只有用户明确要手机系统里的某个声音，或做 `podcast` 要分配声音时，才用 `action=voices` 查看。返回的 `name` 是可传的声音名，`locale` 表示语言，`needs_network` 表示是否需要联网。不要猜编号、读取别的产品的声音目录或许诺不存在的声音克隆。
- 用户指定系统声音时，从当前结果准确匹配。名称有歧义就问；没有该声音就说明并给可用选择，不默默改成别的声音。中文会优先选中文声音；其他语言和多语言混读要核对设备支持。
- 需要联网的声音先考虑网络条件。缺声音或引擎未启用时，按实际错误说明需要用户做什么，不承诺所有语言都能离线合成。
- 用户要修改应用语音设置时，用 `action=request_settings` 发设置卡片，结束这一轮，由用户自己改。卡片发出不代表设置已改，也不会自动给你返回新设置。

## 准备台词

- 自己写的内容只放要读出来的话。去掉 Markdown、引用标记和裸链接，把时间、数字、缩写写成听得懂的说法。参考链接放在随音频发的文字里。
- 用户要逐字朗读时保留原文，不润色、不删句、不把数字改写。需要分段时保持原顺序，不能借分段改内容。
- 单段语音用 `action=speak`，`text` 放正文；可选 `voice` 用刚查到的声音名，`title` 用简短文件名。
- 多人用 `action=podcast`，`script` 是由 `speaker`、`text` 组成的 JSON 数组。`voices` 可选，用 JSON 对象把说话人映射到实际声音名；没有指定时工具自动分配，声音数量不足时可能只靠音调区分。
- 例子：`script=[{"speaker":"A","text":"早上好。"},{"speaker":"B","text":"今天看什么？"}]`。标签写在 `speaker`，不要把“A 说”塞进台词，除非它就是要读的内容。
- 每个文件最多 6000 字符，多人按全部台词合计。更长时按完整句子或段落拆成几份，顺序编号；不把“约二十分钟”当成保证时长。设备或文件大小限制也可能要求更短。

## 检查结果再交付

- 核对工具是否成功，以及返回的 `path`、`engine`、`bytes` 和 `markdown`；用朗读服务时看 `service`，用系统语音时看 `voices`，有 `note` 时照它说明。返回的才是本次实际使用的声音；若与用户要求不符，要说明，不冒充原声完成。
- 没有可播放结果、空文件或只生成部分内容时，不说已完成。成功返回也不证明发音自然；能实际检查音频时再评价质量，没有听过就不说听过。
- 把返回的 `markdown` 原样放进回复，不改路径、不编播放器链接。文件会保存在 `files/voice/`；只报路径不能代替交付播放器。
- 分段音频按顺序全部交付，简短说明每段是什么。用户只要语音时，不再贴一大份重复台词。
- 音频只在本次任务范围内交付。生成了文件，不等于获准发给别人、上传第三方或公开发布。

## 处理失败

- 先按具体错误纠正：超长就分段，脚本格式错就修正 JSON，声音不存在就重新列声音。先保留原文与用户选定的声音，不通过偷偷删内容或换引擎掩盖失败。
- 引擎启动失败、语音包缺失或所选声音合成失败时，说明已完成和未完成部分。换声音需要尊重用户原选择；必要时给设置卡片，而不是反复提交相同错误请求。
- 临时失败可以有限重试；没有新信息时不连续刷调用。不要把一个不透明错误武断说成账号问题或服务故障。
- 只有用户要求稍后重试时，才用 `orbit_task` 保存重试时间、原文来源、声音和次数上限。检查保存结果，不只口头答应；任务不替代当前失败说明。
- 成功、用户取消或达到上限后，取消不再需要的重试任务，报告真实结果，不让重复音频以后又自动发出。
