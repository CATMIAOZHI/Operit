# 在浏览器里准备结账

用户选定商品、需要加购物车或准备下单时读这份。Orbit 只做到付款前，付款交给用户。

## 接上同一笔购物

- 先查当前浏览器页面和已有购物车，复用同一笔购物的任务。另开页面前，弄清前一次是否已经提交或付款。
- 带齐真实商品链接、卖方、款式、型号、尺码、颜色、数量、确认过的收货资料、排除项，以及核实过的总价、币种、送达预估和核价时间。
- 用户只要准备购物车，就不要提交订单。用户要求购买时，先核对具体购买范围；一句“看看这个”不算购买授权。
- 委派浏览子代理时也写清这些条件和“停在付款前，付款由用户完成”，并说明以前的支付失败、拒绝或结果不明。不要交接银行卡号、支付令牌或聊天里的验证码。
- 保留其他有竞争力报价和核价时间，便于价格变化时复查；没有实际看到的价格不能编。

## 检查购物车和条件

- 逐项核对商品、卖方、规格、数量和库存。不要让默认选项、搭售、会员续费或预勾选保险混进订单。
- 按最终到手价检查运费、税费、满减、券、订阅价及适用资格；不把需要凑单或新客资格的价格当成人人可用。
- 核对收货地址、配送方式、预计送达和退换条件。只填写任务必需的资料，不在聊天中完整复述地址等私人信息。
- 价格涨了、优惠失效或配送变慢，先复查已知替代报价，再告诉用户变化和可选做法。不要擅自换商品、提高预算或接受更差条件。

## 批准、接管和核实

- 提交前给用户看商品、数量、规格、配送和总价。缺少具体下单授权时，用 `orbit_request_approval` 请求批准，结束这一轮等待；同一范围已明确授权时不重复申请。
- 登录可用 `orbit_vault`；需要密码、验证码或人机验证时用 `orbit_browser_handoff`。银行卡和付款始终由用户接手，包括已保存的支付方式。
- 交出浏览器后结束这一轮，不同时操作。用户交还后重新读取页面，确认实际状态。
- 超时、报错或跳回首页不证明失败。先查订单、购物车和获准读取的商家确认消息；支付仍不明时请用户核对，不另建订单或再次付款。
- 只凭商家实际证据报告完成，写清订单号、应付或已付状态和预计送达。加入购物车、等待付款、付款成功、订单确认要分开说。
